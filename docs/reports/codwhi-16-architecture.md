# Mobile trust boundaries

The phone records audio only. The paired server runs the transcription model. Shared TypeScript owns the existing Noise client, canonical protocol codecs, pairing approval, session sequencing, final segment assembly, and a bounded audio queue. Native code owns platform privileges and the editor.

The Android IME captures the originating InputConnection and editor generation. A fresh run can consume that lease only after the user explicitly requests Stop, the matching session finishes successfully, and the editor remains active. Commit consumes the lease before calling commitText. Cancel, input restart, unbind, finish, keyboard hide/switch, selection change, lock, and service destruction invalidate it synchronously before asynchronous cleanup. No surrounding text is read. Password input variations and TYPE_NULL fields disable Record.

AudioRecord supplies mono 16 kHz PCM16 little-endian frames of 3200 bytes. Every bridge event has a run id, sequence, and explicit base64 payload. Eight unacknowledged native frames is the limit. JavaScript acknowledges only after validating sequence and appending to a bounded 320000-byte queue. The sender preserves order, respects flow pauses and native transport byte reservations, and sends at most 3200 bytes every 100 ms. Only the final frame may be below 640 bytes. Overflow, missing frames, timeout, authentication failure, and protocol failure terminate the run. There is no automatic recording replay.

A successful done message alone cannot authorize insertion. The native lease requires explicit Stop. The shared session also requires finish to have been sent. Cancel closes the connection, rejects completion, and prevents delayed done or final callbacks from supplying text.

The application owns ReactHost. VoiceInputService starts and tracks a HeadlessJsTaskContext task without a visible Activity. The JavaScript task registers audio and command listeners before acknowledging native readiness. Its promise stays alive until success, cancel, or failure. The native ready call rejects stale runs. The task permits foreground execution and has a bounded lifetime. Tests force-stop the app before selecting the IME, so the JS engine starts from bundled bytecode without Metro.

The native vault stores an AES-GCM envelope in Android noBackupFilesDir. Android Keystore holds the wrapping key. Temporary file replacement preserves the previous approved envelope on a failed write. iOS uses a device-only Keychain item with atomic update. The Noise identity private key is exportable JavaScript memory during a session. It is not a hardware-held non-exportable identity. Native SecureRandom or SecRandomCopyBytes supplies all randomness; a missing native bridge fails closed. There is no Math.random fallback.

External pairing tokens, encrypted server frames, protected stored data, and native bridge events are parsed at their boundaries. Pinned server keys and Noise authenticate the remote peer. TLS validation remains enabled. Protocol ciphertext uses the existing IKpsk2 pairing and IK session implementation, existing prologues, tagged messages, and independent directional rekeys every 10000 successful messages without nonce reset. No new crypto or server protocol was introduced.

The pairing token and PCM are never logged. Transcript output stays in the editor or foreground recorder. Pairing failure preserves the previous envelope. The Android backup flag is disabled; the iOS Keychain item is not synchronizable or restorable to another device.

Dependency choices are React Native 0.88.1 with React 19.3.0 from its official template; native platform capture and vault APIs instead of microphone/storage plugins; @scure/base for canonical base64 and hex; @stablelib/utf8 for the mobile TextEncoder shim only; and react-native-url-polyfill for WHATWG endpoint parsing in Hermes. Babel, Metro, CLI, Gradle plugin, codegen, and the Hermes compiler are pinned build dependencies. The Hermes compiler version matches the React Native package. Context7 tools were not exposed in this session; vendor documentation, published package contents, and installed source supplied the compatibility evidence.

## CODWHI-16 P1 fix round

Protocol JSON decoding delegates UTF-8 validation to the ECMAScript native `decodeURIComponent` implementation. `@scure/base` hex encoding supplies percent-encoded bytes. This adapter contains no UTF-8 parser, works without TextDecoder in Hermes, preserves one leading BOM and literal percent text, and rejects invalid continuation leads, overlong sequences, truncation, surrogate encodings and values above U+10FFFF. Stablelib 2.1.0's installed decoder was audited and reproduced accepting `84 8c` as Č. Its protocol dependency was removed; mobile still uses its encoder in bootstrap.

React Native 0.88.1's JS WebSocket and both native modules were inspected. The JS implementation never supplies bufferedAmount, Android sendBinary enqueues directly into OkHttp, and iOS sendBinary enqueues into SocketRocket without reporting completion. The mobile adapter therefore uses a dedicated native socket module rather than that transport. The existing Wire and session interfaces, Noise framing and server protocol remain unchanged.

The shared adapter reserves at most 64000 ciphertext bytes across queued and in-flight frames before crossing the native bridge. It sends one frame at a time, and releases its reservation only when the native promise reports drain. Android additionally rejects overlapping/oversized native sends and polls real OkHttp queueSize until zero, with a ten-second deadline. iOS uses one URLSessionWebSocketTask send at a time and releases bytes only from its completion handler, with the same deadline. Both adapters cancel on close, fail pending operations, bound socket count to four, and discard stale callbacks. Normal TLS validation remains enabled; iOS accepts wss only. Android's packaged release/verification network security policies still govern its endpoints.

An undefined-value fallback was rejected because it cannot bound RN's native queue. Server-only flow control was rejected because it cannot arrive on a stalled link. An async native queue-size getter alone was rejected because it leaves bridge operations unreserved. Native completion plus a bounded shared reservation provides the bound on both platforms without changing the protocol or crypto.

MockWebServer 4.9.2 is a test-only dependency matching the installed RN OkHttp 4.9.2. It supplies a real WebSocket peer that blocks reads; the test verifies an actual nonempty OkHttp queue remains unacknowledged and fails on the deadline. No production socket dependency was added. Apple source is statically inspected only on Linux and still requires Xcode/device validation.


Primary contracts checked in this fix round are the [ECMAScript Decode operation](https://tc39.es/ecma262/multipage/global-object.html#sec-decode), [OkHttp 4.9.2 writer source](https://github.com/square/okhttp/blob/parent-4.9.2/okhttp/src/main/kotlin/okhttp3/internal/ws/RealWebSocket.kt), and [Apple send completion](https://developer.apple.com/documentation/foundation/urlsessionwebsockettask/send(_:completionhandler:)). Context7 was unavailable after a direct attempt. Installed RN source and primary vendor sources supplied the evidence.
